# GameAP i18n (Internationalization)

## Overview

The GameAP frontend application supports multiple languages with automatic language detection and easy switching.

## Supported Languages

The language list is **dynamic**: the backend serves the available locales at `GET /lang` (derived from the
translation files in the merged i18n filesystem, plugin-contributed ones included), and the frontend builds its
switcher from that endpoint — there is no hardcoded list. Built-in locales:

- **English (en)** - Default language
- **Russian (ru)**
- **Spanish (es)**
- **German (de)**

## How It Works

### 1. Language Detection Priority

The system detects the user's language in the following order:

1. **localStorage** - `gameap_lang` key (user preference)
2. **HTML lang attribute** - `<html lang="...">`
3. **Browser language** - `navigator.language`
4. **Default** - Falls back to English (`en`)

### 2. Translation Loading

Translations are loaded **synchronously** before the Vue app initializes:

- The available locales come from `GET /lang` → `[{ "code", "name", "native_name" }, …]`, stored in
  `window.gameapLanguages`
- Files located at `/lang/<code>.json` (e.g. `/lang/en.json`, `/lang/ru.json`)
- Loaded via XHR in `index.html`
- Stored in `window.i18n` global object
- Language code stored in `window.gameapLang`

Each translation file carries a top-level `_language` label that `GET /lang` reads to populate the switcher:

```json
{ "_language": { "name": "English", "native_name": "English" }, "…": {} }
```

> **Plugins** may contribute `/lang/*.json` files via their `GetAssets` capability, layered **above** the
> built-in translations. A plugin locale with a `_language` label appears in the switcher automatically (no
> frontend change) — so a plugin can add a brand-new locale (e.g. `es.json`). A plugin `en.json` instead
> shadows the core `en.json` wholesale (not a key-level merge). See `pkg/plugin/README.md` →
> "Contributing translation & frontend files".

### 3. Build Process

There is no translation copy step in the frontend build — `package.json` has **no**
`prebuild` script. Translation files are embedded into the backend binary via
`//go:embed *.json` (`internal/i18n/i18n.go`) and served at `/lang/<code>.json` straight
from the embedded filesystem.

**Rebuilding the backend is the only step needed** to pick up translation changes;
`npm run build` for the frontend does not involve translations at all.

## Usage in Vue Components

### Using Translations

```vue
<template>
  <div>
    <h1>{{ trans('auth.sign_in') }}</h1>
    <p>{{ trans('auth.throttle', { seconds: 60 }) }}</p>
  </div>
</template>

<script setup>
// trans is available globally, no import needed
</script>
```

### Changing Language

```vue
<template>
  <button @click="switchToRussian">Русский</button>
  <button @click="switchToEnglish">English</button>
</template>

<script setup>
const switchToRussian = () => {
  changeLanguage('ru');
}

const switchToEnglish = () => {
  changeLanguage('en');
}
</script>
```

### Getting Current Language

```vue
<script setup>
import { getCurrentLanguage } from '@/i18n/i18n';

const currentLang = getCurrentLanguage(); // Returns a locale code, e.g. 'en', 'ru', 'es', 'de'
</script>
```

## Adding New Languages

The language list is dynamic — no frontend source changes are required.

1. **Add the translation file** to `internal/i18n/` with a top-level `_language` label (English name plus the
   language's own name):
   ```json
   // internal/i18n/de.json
   {
     "_language": { "name": "German", "native_name": "Deutsch" },
     "auth": { "sign_in": "Anmelden" }
   }
   ```

2. **Rebuild the backend.** The file is embedded (`//go:embed *.json`), `GET /lang` now lists `de`, and the
   frontend picks it up automatically. Plugins can add a locale the same way via `GetAssets` (see
   `pkg/plugin/README.md`).

> Plural rules for a new language default to the English-style rule until added to
> `web/frontend/js/i18n/plurals.js` and `pluralForms` in `web/frontend/js/i18n/i18n.js`.

## API Reference

### Functions

#### `trans(key, params)`
Translate a key with optional parameter replacement.

```javascript
trans('auth.sign_in')  // "Login"
trans('auth.throttle', { seconds: 60 })  // "Too many login attempts. Please try again in 60 seconds."
```

#### `changeLanguage(langCode)`
Change the application language (requires page reload).

```javascript
changeLanguage('ru')  // Saves to localStorage and reloads page
```

#### `getCurrentLanguage()`
Get the current language code.

```javascript
const lang = getCurrentLanguage()  // Returns a locale code, e.g. 'en', 'ru', 'es', 'de'
```

#### `pluralize(choice, count)`
Get pluralized form based on count (uses language-specific rules).

```javascript
pluralize('items', 1)   // "item"
pluralize('items', 5)   // "items"
```

## Testing

### Test Language Detection

1. **Open browser DevTools** → Console
2. **Check current language**:
   ```javascript
   console.log(window.gameapLang)  // 'en', 'ru', 'es', 'de', …
   ```

3. **Check loaded translations**:
   ```javascript
   console.log(window.i18n.auth.sign_in)  // "Login" or "Войти"
   ```

### Test Language Switching

1. **Open browser console**
2. **Switch language**:
   ```javascript
   changeLanguage('ru')  // Page will reload with Russian
   ```

3. **Check localStorage**:
   ```javascript
   localStorage.getItem('gameap_lang')  // 'ru'
   ```

## Console Messages

When the app loads, you'll see these messages:

```
[i18n] Loaded en translations successfully
```

Or in case of fallback:

```
[i18n] Failed to load ru translations: 404
[i18n] Fallback to English translations
```

## File Structure

```
web/frontend/
├── index.html              # Language detection & loading script (GET /lang, GET /lang/<code>.json)
└── js/
    └── i18n/
        ├── i18n.js        # Translation utilities + pluralForms per locale
        └── plurals.js     # Plural forms for different languages

internal/i18n/             # Source of truth (backend): embedded via //go:embed *.json and
│                          # served at /lang/<code>.json (no copy under web/frontend/public)
├── en.json
├── ru.json
├── es.json
└── de.json
```

## Notes

- Translations are loaded **before** Vue app initialization
- Language switching requires a **page reload** to load new translations
- User preference is saved in **localStorage**
- Fallback to English if requested language fails to load
